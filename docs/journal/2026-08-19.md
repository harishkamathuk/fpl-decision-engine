# 2026-08-19

## Issue #47: First-Class Scenario Definitions

Implemented the narrow definition-only slice for promoting proven optimiser scenarios into a
canonical application/domain concept.

### Implementation

- Added immutable `ScenarioConstraints` and `ScenarioDefinition` domain models.
- Kept the five supported constraint meanings explicit: `must_include`, `excluded`,
  `forced_starters`, `forced_captain` and `forced_vice_captain`.
- Exposed captain/vice-captain implications through canonical `required_starters` and
  `required_in_squad` properties without requiring redundant input declarations.
- Added a strict application JSON adaptor supporting the existing top-level constraint fields and a
  fixed `constraints` wrapper.
- Resolved direct canonical UUIDs and exact namespace-scoped `Player.external_refs` into canonical
  UUIDs before constructing the domain definition.
- Rejected unknown fields, unresolved or ambiguous identities, per-collection duplicates and each
  agreed direct contradiction.
- Stored collection constraints as `frozenset`s so equivalent input ordering produces equal canonical
  definitions.

### Boundaries preserved

The adaptor has no projection argument and does not mutate forecast records. It does not invoke the
solver, check budget/formation/club/full-squad feasibility, create DecisionRuns, or introduce
ScenarioRun/ScenarioComparison concepts. Forecast generation, projection values, evidence ingestion
and optimiser execution were intentionally left unchanged for future scoped issues, with execution
and comparison deferred to Issue #48.

### Validation

Focused deterministic coverage includes all five constraint semantics, exact identity success,
unresolved and ambiguous references, canonical UUID storage, duplicate and contradiction handling,
valid redundancy, strict unknown-field rejection, order-independent canonicalisation, and forecast
isolation.

## Issue #62: Structured Evidence Chronology Errors

Normalised the structured team-news provider's `processed_at` chronology failure to
`ProviderDataError` without changing its existing message or availability semantics. Removed the
redundant timezone-awareness check and added regression coverage for both processing-before-
observation and publication-after-observation, including the provider boundary error type.

### Validation

The focused infrastructure and application integration suites pass. Full Ruff, Pyright and pytest
results are recorded with the implementation changes.
