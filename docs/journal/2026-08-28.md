# 2026-08-28

## Issue #85: downstream history/comparison operational integration

Implemented the remaining Issue #85 slice: wiring the already-built immutable
analytical artefact capability downstream of a completed baseline run.

The #102 foundation and #104/#105 generator-contract refinements were already in
place. This slice adds the smallest operational seam that was still missing:

- an immutable `DecisionBundleV1` read/parse seam (`parse_decision_bundle`,
  `load_decision_bundle`) that verifies the recorded content hash against the
  exact persisted bytes and reconstructs the serializer's `formation` label and
  raw `gameweek` value back into the v1 model;
- `AnalyticalHistoryService`, which resolves previous state strictly from
  `current_run.previous_run_id` (never re-running authoritative-run resolution
  and never guessing), loads both immutable bundles, classifies by
  `recommendation.identity` only, and drives the existing
  `AnalyticalArtifactService`;
- concrete `HistoryGenerator`/`ComparisonGenerator` implementations of the
  existing #104 contract;
- a `touchline analytics <run_id>` command that surfaces analytical failure as
  explicit error output without touching the run record.

### Decisions

- **Artefact hashes are provenance, not the change predicate.** CHANGED/UNCHANGED
  is decided exclusively by `recommendation.identity` equality. A bundle whose
  bytes differ (e.g. config fingerprint) but whose recommendation identity is
  equal stays UNCHANGED; this is covered by an explicit test.
- **Previous state is resolved before anything is published.** A missing, legacy,
  decision-less or content-drifted previous state fails the whole analytical
  invocation explicitly with nothing published, so there is never a comparison
  against guessed state.
- **No lifecycle coupling.** The seam reads the current run via
  `RunRecordService.get_run`, requires COMPLETED/AUTHORITATIVE, and never mutates
  records. History/comparison was deliberately not added to
  `ORCHESTRATOR_STAGES`.
- **No new schemas or contracts.** `DecisionBundleV1`, the analytical generator
  inputs and the analytical artefact schemas are unchanged; only the read seam,
  concrete generators and the integration service were added.

### Risks / open questions

- The seam picks the latest `RecordedDecision` when a run records several; today
  the baseline path records exactly one, so the choice is unambiguous in
  practice.
- Review artefacts (#107/#108, referenced-artefact wiring) remain explicitly out
  of scope; only history and comparison are integrated.
