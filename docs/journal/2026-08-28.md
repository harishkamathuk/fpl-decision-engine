# 2026-08-28

## Issue #86: scenario lifecycle and freeze provenance

Implemented the minimum immutable lifecycle seam for scenario candidates:

- prepared candidates are content-addressed by source identity, evidence identity and
  canonical scenario content;
- review produces immutable per-scenario classifications with machine-readable reason
  codes, applying INVALID_REFERENCE, INAPPLICABLE, MISSING_PROJECTION, REDUNDANT and
  VALID in the approved order;
- only VALID scenarios require INCLUDE/EXCLUDE disposition;
- promotion rejects stale, superseded, incomplete or blocking candidates and derives a
  frozen artefact without changing reviewed content;
- frozen artefacts retain all reviewed provenance while exposing only VALID+INCLUDE
  scenarios as executable content;
- frozen bytes are written content-addressably with no-overwrite protection.

The lifecycle does not add states to RunRecord, alter optimiser semantics, or redesign
orchestration. Evidence and source identities are supplied by the existing application
boundaries and compared directly at promotion time.

Added deterministic acceptance coverage for T1–T12, including blocking classifications,
staleness, no-overwrite persistence, Hirst applicability/no-op semantics, deterministic
hashes, disposition enforcement, derivational promotion, and elapsed-time handling.

Independent review corrections B1–B4 were added without changing approved semantics:
atomic no-replace frozen publication, domain-enforced promotion linkage, exact reviewed
scenario derivation, and INAPPLICABLE reason integrity. Regression tests cover concurrent
idempotent publication, conflicting immutable destinations, direct linkage mismatches,
content tampering, and reason tampering.

Validation: Ruff, Pyright, `git diff --check`, and the full deterministic suite passed
(538 tests).
