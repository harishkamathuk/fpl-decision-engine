### Reverse-mapping ordering fix

`_actual_choice()` previously reconstructed `SubmittedDecision` by reverse-mapping observed FPL element IDs to canonical UUIDs in the element-ID order seen on the observed snapshot. Because `DecisionSelection` requires canonical `str(uuid)` ordering for `squad_ids` and `starting_xi_ids`, any observed snapshot whose element-ID order diverged from UUID order produced an identity that either failed validation or silently lost canonical ordering. `_actual_choice()` now sorts the reverse-mapped `squad_ids` and `starting_xi_ids` by `str(uuid)`, while leaving `bench_ids` order, captain/vice identities, and the explicit reverse-mapping seam untouched. Tests were converted from `UUID(int=...)` inference to deterministic canonical UUIDv5 identities and now cover identical post-exec state, canonical identity preservation, squad/XI permutations, outfield-bench reorder, and fail-closed missing/duplicate mappings.
