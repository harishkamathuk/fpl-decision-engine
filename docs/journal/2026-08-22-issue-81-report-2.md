## Non-blocking findings

1. **Authoritative uniqueness is derived, not enforced at promotion time** *(high priority; resolves before #84)*
   - `RunRecordService.promote_run` → `RunRecordLedger.resolve_authoritative_run`.
   - Probe-verified: promoting Run B for a season/GW that already has an authoritative Run A **succeeds without any check**; both records persist with `state=authoritative`. Resolution picks the latest approval timestamp; if approval timestamps tie, `create_run` for that GW fails with "ambiguous" at *lookup*.
   - #80 sanctions the derived model ("The current authoritative run is derived from recorded authority events; superseded runs remain historically intact"), so "at most one current authoritative run per season/Gameweek" holds for every derivable state; the tie case is the only violation and is not explicitly allowed by #80 — a narrow defect surfaced only at lookup.
   - Required correction before #84: check for an existing authoritative run for the same (season, Gameweek) at promotion and either reject, or require explicit supersession recording the superseded run id in the promotion `AuthorityEvent`. Confirm explicit-vs-derived supersession semantics with the #80 owner (06.02); do not decide it in code.
2. **Concurrent-writer TOCTOU inside `save`** *(low; required before #84)* — the raw-read/`expected_raw` check and `os.replace` are not atomic; two writers passing the check within the window can both commit and the last replace silently wins. Service-level stale commits are caught. Fix for #84: per-file `flock` around read-check-replace, or atomic compare-and-swap.
3. **No directory fsync after `os.replace`** *(low)* — the temp file is fsynced but the ledger directory is not; power-loss window between rename and directory-entry durability. Standard hardening: fsync the directory after replace (and after `mkdir`).
4. **`close_run` accepts `by` but never records it** *(low)* — audit trail for who closed a run is silently dropped; record it or remove the parameter.
5. **Duplicate-decision policy inconsistent with artefact policy** *(low)* — `record_artefact` rejects same-name conflicts; `record_decision` appends duplicates with differing metadata. Pick one policy and document it.
6. **Transition state machine lives only in the service** *(informational, acceptable)* — probe confirmed `RunRecordLedger.save` accepts structurally-valid but transitionally-impossible history (PASS with no prior PENDING/RUNNING). #84's orchestrator must route all writes through the service.
7. **Lax pydantic coercion on v1 reads** *(informational)* — `"gameweek": "1"` is coerced and canonicalised on rewrite; `extra="forbid"` correctly rejects unknown fields (no silent round-trip data loss).
8. **Missing in-suite test: cross-Gameweek implicit resolution** *(test hygiene)* — probe verified GW1-authoritative → GW2 create yields `previous_run_id=None` (correct per #80's same-season/Gameweek domain); add to `tests/application/test_run_record_service.py`.
