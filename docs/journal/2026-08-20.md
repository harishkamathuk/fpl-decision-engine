# 2026-08-20

## Issue #61: Premier League injury evidence collector

The required transport gate succeeded with one ordinary GET to
`https://www.premierleague.com/en/latest-player-injuries`: HTTP 200, HTML content type, and
server-rendered injury/last-updated content were present in the raw response. No browser automation
or additional runtime dependency was introduced.

### What changed

- Added a bounded collector for the single Premier League latest-injuries page.
- Captured exact response bytes before parsing below an explicit caller-supplied output root.
- Added immutable capture manifests with URL, resolved URL, UTC capture time, byte count, SHA-256,
  content type, page last-updated text/time and parser version.
- Parsed only the observed club-heading plus `Player` / `Injury` / `Latest` table shape.
- Treated complete `-` placeholder rows as no club injury entry.
- Preserved page publication time with UK GMT/BST semantics and kept it distinct from capture time.
- Mapped exact team-scoped full names to stable `fpl_code` values from contemporaneous bootstrap
  data, with bootstrap-validated explicit overrides only.
- Emitted the existing #57 structured evidence artefact and lightweight row-level evaluation data.
- Preserved raw capture and failure evaluation data when parsing or identity mapping failed.

### Boundaries preserved

The collector emits only `doubtful`/`injury`/`indicative` for explicit injury text and
`unknown`/`injury`/`ambiguous` for a real player with a blank injury field. It does not infer
availability, expected minutes, start probability or projected points, and it does not alter the
#57 provider, availability assessment or optimiser.

### Validation

Frozen HTML and bootstrap fixtures cover successful capture, exact SHA-256 provenance, UK BST
publication parsing, missing publication time, exact team-scoped identity, reviewed overrides,
unmapped and ambiguous identities, non-unique/missing stable codes, placeholder rows, malformed
source shape, immutable no-overwrite behaviour, evaluation classification and real consumption by
`StructuredTeamNewsEvidenceProvider`. Focused tests, Ruff and strict Pyright pass. The full suite
passes 233 tests with two unrelated Parquet timezone failures in this slim environment because the
system `UTC` tz database is absent; CI images with tzdata are expected to cover those existing tests.

## Issue #65: Premier League team-news collector CLI

### What changed

- Added a thin `fpl collect` command that delegates entirely to the existing Issue #61
  `PremierLeagueInjuriesCollector`, invoking its live `collect()` path with the caller-supplied
  bootstrap and output root.
- The command prints the capture id, capture directory, structured evidence path and evaluation
  path on success, and exits non-zero with an explicit `error [code] provider=...` message when a
  provider failure occurs, following the existing `sync` CLI convention.
- No collector, parser, identity-mapping, #57, evidence or persistence logic was moved into the
  CLI; the wrapper only instantiates the existing public collector API.

### Validation

Frozen HTML and bootstrap fixtures drive deterministic `CliRunner` tests for help output, a
successful offline capture through the collector's `collect_response` seam, and provider failure
propagation. Focused CLI tests, Ruff and strict Pyright pass; the full suite retains only the two
known Parquet timezone baseline failures of this slim environment.
