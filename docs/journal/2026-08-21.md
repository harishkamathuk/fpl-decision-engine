# 2026-08-21

## GW1: First live Touchline Gameweek decision

Touchline completed its first live pre-deadline Gameweek decision cycle for
GW1 of the 2026/27 FPL season.

The end-to-end workflow was rehearsed and then executed against the real GW1
deadline. The resulting team was reviewed and submitted on the FPL site before
the deadline.

### Operational outcome

- Completed the GW1 end-to-end decision workflow using frozen pre-deadline
  inputs and projections.
- Generated and reviewed the unconstrained baseline recommendation.
- Exercised scenario analysis against plausible alternative selection
  hypotheses.
- Updated and submitted the final GW1 team on the FPL site.
- Preserved the pre-deadline decision state required for later realised-outcome
  evaluation.
- Established a repeatable operational process that can be reused and refined
  for subsequent Gameweeks.

## Scenario-analysis learning

Operational scenario use confirmed that constraint-only scenarios using the
same projections and optimiser objective as the unconstrained baseline should
not normally outperform that baseline.

The baseline searches the complete feasible solution space, while scenarios
such as forced inclusion, exclusion, starter or captain constraints search a
subset of that space.

The useful interpretation of these scenarios is therefore the projected
opportunity cost and robustness of the baseline recommendation rather than
whether the constrained alternative can beat the baseline under the same
model.

This distinction was handed back to the relevant scenario, optimisation,
projection and validation design conversations for future refinement. No
additional implementation was initiated from this observation.

## Local projection generation

Local execution of the external `fpl-forecast` project was established for
future Gameweek runs.

This removes reliance on waiting for a previously generated remote projection
artefact when a fresher pre-deadline forecast is required.

The external project remains separate from Touchline. Local forecast generation
does not change Touchline's existing projection-provider boundary or imply
integration of the upstream forecasting implementation into the application.

## External football evidence

The Premier League team-news evidence capability delivered through Issues #61
and #65 is now available for operational use.

The collector can retrieve and preserve the bounded Premier League injury
source and emit structured evidence consumable by the existing Touchline
evidence-provider boundary.

The immediate objective is now evidence accumulation rather than further
development. Captures should be collected across future Gameweeks so source
freshness, usefulness and reliability can be evaluated before any forecast
recalibration work is justified.

## Issue #68: Frozen decision evaluation

The first bounded implementation slice of the wider Issue #12 evaluation
capability was completed and merged.

The resulting evaluator provides the leakage-safe boundary required to compare
the preserved pre-deadline baseline, scenarios and human decision against
post-Gameweek realised outcome evidence.

The next meaningful step is operational rather than architectural: once GW1
results are known, prepare the realised `OutcomeEvidenceV1` and exercise the
evaluator against the first genuine Touchline decision.

Automated post-Gameweek outcome acquisition and candidate scoring remain a
separate potential follow-up rather than being added to the evaluator.

## Issue #70: Touchline README branding

The repository README was updated so the application's user-facing project
name is **Touchline**.

The change is branding only. Existing technical identifiers remain unchanged,
including the `fpl-decision-engine` repository identity, Python package names
and `fpl` CLI.

## Current project position

GW1 marks the transition from primarily constructing Touchline capabilities to
operating and evaluating them against real FPL decisions.

The immediate development priority is deliberately constrained:

1. allow GW1 to complete;
2. capture realised outcome evidence;
3. run the first frozen-decision evaluation;
4. continue accumulating external football evidence;
5. use observed operational and evaluation evidence to decide which backlog
   capability should be promoted next.

Issue #48 and other larger feature areas remain deferred unless real Gameweek
operation demonstrates that they are required.

The governing lesson from GW1 is to prefer:

    operate → observe → evaluate → improve

over continuing to add features simply because additional capabilities are
available to build.
