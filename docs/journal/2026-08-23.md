# 2026-08-23

## Issue #85: derived immutable analytical artefacts

Implemented a bounded downstream capability for history, comparison and review
artefacts. Analytical outputs are immutable, content-addressed JSON documents whose
identities bind completed-run provenance, evidence identity, generator name/version
and canonical analytical content. Publication uses same-filesystem temporary files
and atomic hard-link/no-replace semantics; equivalent regeneration is idempotent and
conflicting bytes never overwrite an existing artefact.

The application service accepts only completed or authoritative evidence-bound runs
with recorded decision provenance. It reads immutable RunRecord data but has no
RunRecord repository dependency and cannot change run state. Generator failures remain
downstream failures and leave completed decision runs untouched.

No `AnalysisRun` or second lifecycle was introduced. Issue #84 orchestration,
RunRecord completion, EvidenceIdentity, optimiser and forecast behaviour were not
changed.

## Issue #104: analytical generator input contracts

Refined the #85 generator boundary so history, comparison and review generators
receive explicit immutable input contracts rather than a RunRecord. Each contract
contains source/decision run identity, evidence identity, generator name/version and
all preloaded type-specific values. Resolved values are held as canonical JSON in a
frozen value object, preventing nested mutation while giving generators a fresh
decoded copy.

The application layer still validates completed-run provenance and publishes through
the existing immutable artefact repository. Generators have one pure input-only
method and no repository, RunRecord, latest-record or previous-record dependency.
Analytical identity, content hashing, persistence and lifecycle semantics are
unchanged.
