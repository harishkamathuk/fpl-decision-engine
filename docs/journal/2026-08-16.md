## Scenario Framework Matures into Decision Analysis Layer

### Summary

Today's work significantly advanced the decision-engine concept beyond a squad optimiser.

The GW1 scenario harness, originally created as an operational tool to test alternative squad ideas, demonstrated that it is becoming a broader **decision analysis capability**.

The key insight:

> The optimiser answers "what is the best decision given the model assumptions?"  
> The scenario framework answers "what happens if I believe something different?"

This distinction is central to the future architecture.

The scenario workflow was moved to follow a clearer operational boundary:

```text
fpl-ops

    +-- scripts
    +-- validation
    +-- schemas
    +-- documentation


fpl-inputs
    |
    +-- snapshots
    +-- projections

    +-- frozen scenario sets


fpl-state
    |
    +-- DecisionRuns
    +-- DecisionBundles
```

This establishes an important principle:

> Human-authored decision inputs are data, not application code.

Scenario definitions are now treated as versioned operational artefacts.

## FPL Forecast Comparison Experiment

A second benchmark exercise was performed against the FPL Forecast recommended squad.

The objective was not to prove one model was superior, but to understand why recommendations differed.

The comparison revealed an important architectural distinction.

---

### Discovery: Scenario and Benchmark are different concepts

Initially, an external recommended squad was represented as a scenario.

This exposed a limitation.

A scenario means:

> "Optimise again under this additional assumption."

Example:

```text
Force Haaland

Question:
What is the optimal squad if Haaland must be included?
```

An external recommendation means:

> "Evaluate this existing decision."

Example:

```text
FPL Forecast squad

Question:
How does this decision compare against my optimiser?
```

These are different capabilities.

## Architectural Insight

The future model should separate:

### Scenario

A controlled counterfactual question.

```text
ScenarioDefinition
        |
        ↓
Optimiser
        |
        ↓
ScenarioRun
```

Examples:

- What if Haaland?
- What if Saka captain?
- What if I avoid a player?

---

### Benchmark Evaluation

A fixed external decision.

```text
External Squad
        |
        ↓
Evaluation Engine
        |
        ↓
Comparison
```

Examples:

- FPL Forecast squad
- FPL Scout squad
- My manual selection
- League rival squad

## Key Product Insight

The value proposition is becoming clearer.

This project is not simply competing with prediction models.

The differentiation is:

> A decision intelligence layer that allows different forecasts, opinions and recommendations to be interrogated against a deterministic optimisation engine.

External models become inputs and benchmarks, not competitors.

## Important Learning from FPL Forecast Comparison

The FPL Forecast squad and optimiser produced different decisions despite using the same general projection source.

This suggests differences may arise from:

- objective function;
- optimisation constraints;
- risk assumptions;
- squad structure preferences;
- captain strategy;
- bench strategy.

The next logical question is therefore not:

> "Which model is correct?"

but:

> "What assumptions explain the difference?"
