# 2026-08-20

## Issue #61: Premier League injury evidence collector

The required transport gate succeeded with one ordinary GET to
`https://www.premierleague.com/en/latest-player-injuries`: HTTP 200, HTML content type, and
server-rendered injury/last-updated content were present in the raw response. No browser automation
or additional runtime dependency was introduced.

### What changed

- Added a bounded collector for the single Premier League latest-injuries page.
- Captured exact response bytes before parsing below an explicit caller-supplied output root.
- Added immutable capture manifests with URL, resolved URL, UTC capture time, byte count, SHA-256,
  content type, page last-updated text/time and parser version.
- Parsed only the observed club-heading plus `Player` / `Injury` / `Latest` table shape.
- Treated complete `-` placeholder rows as no club injury entry.
- Preserved page publication time with UK GMT/BST semantics and kept it distinct from capture time.
- Mapped exact team-scoped full names to stable `fpl_code` values from contemporaneous bootstrap
  data, with bootstrap-validated explicit overrides only.
- Emitted the existing #57 structured evidence artefact and lightweight row-level evaluation data.
- Preserved raw capture and failure evaluation data when parsing or identity mapping failed.

### Boundaries preserved

The collector emits only `doubtful`/`injury`/`indicative` for explicit injury text and
`unknown`/`injury`/`ambiguous` for a real player with a blank injury field. It does not infer
availability, expected minutes, start probability or projected points, and it does not alter the
#57 provider, availability assessment or optimiser.

### Validation

Frozen HTML and bootstrap fixtures cover successful capture, exact SHA-256 provenance, UK BST
publication parsing, missing publication time, exact team-scoped identity, reviewed overrides,
unmapped and ambiguous identities, non-unique/missing stable codes, placeholder rows, malformed
source shape, immutable no-overwrite behaviour, evaluation classification and real consumption by
`StructuredTeamNewsEvidenceProvider`. Focused tests, Ruff and strict Pyright pass. The full suite
passes 233 tests with two unrelated Parquet timezone failures in this slim environment because the
system `UTC` tz database is absent; CI images with tzdata are expected to cover those existing tests.

## Issue #68: Evaluate a frozen Gameweek decision without look-ahead leakage

### Implementation boundary

Delivered a leakage-safe evaluator that compares frozen pre-deadline baseline
recommendations against post-deadline realised outcomes. The evaluator is a pure
function with no dependency path to the optimiser, forecast provider, or any IO.
It composes already-preserved artefacts only.

### Evaluation boundary

```
frozen DecisionBundleV1 baseline
+ DecisionRun (optimiser provenance)
+ tuple[(DecisionRun, DecisionBundleV1)] pre-deadline scenarios
+ tuple[DecisionBundleV1] separately preserved candidate bundles
+ SubmittedDecision human choice
+ OutcomeEvidenceV1 post-deadline realised points
    → DecisionEvaluationV1 deterministic output
```

### Contracts introduced

- `OutcomeEvidenceV1` — post-deadline realised points per candidate selection
  identity; strictly separate from pre-deadline evidence.
- `DecisionEvaluationV1` — deterministic evaluation output with baseline,
  scenario, human decision, comparison, validation and forecast observation
  sections.
- `evaluate_decision()` — pure evaluator function with explicit temporal and
  provenance guards.

### Leakage protections enforced

1. Baseline projection `generated_at` must precede decision cutoff.
2. Baseline availability cutoff must precede decision cutoff.
3. Outcome `observed_at` must follow decision cutoff.
4. Scenario `created_at` must precede decision cutoff.
5. Scenario `decision_at` must not exceed baseline cutoff.
6. Scenario projection `generated_at` must precede decision cutoff.
7. Scenario must share the same frozen input basis as baseline.
8. Human choice `recorded_at` must not exceed decision cutoff.
9. Explicit human choice must agree with preserved `actual_choice`.
10. Candidate bundle projection `generated_at` must precede decision cutoff.
11. Candidate bundle availability cutoff must precede decision cutoff.
12. Candidate bundle must share the same frozen input basis as baseline.
13. Candidate bundle `decision_at` must not exceed baseline cutoff.
14. Season and gameweek consistency enforced across all inputs.
15. No fallback to current/latest data; no provider or optimiser calls.

### Candidate bundle handling

The `candidate_bundles` parameter accepts separately preserved pre-deadline
candidate bundles. These are subject to the same temporal and provenance
leakage rules as scenarios but are never represented as scenarios. They are
used solely to recover the already-preserved frozen projected xPts when the
human choice matches neither the baseline nor a preserved scenario. When no
such bundle exists, the evaluator raises `MissingFrozenScoreError` explicitly
rather than reconstructing missing historical evidence.

### Tests

Evaluation tests (48) include the 7 mandatory tests from the issue plus
focused tests for outcome identity correctness, temporal guards, run/bundle
provenance consistency, solver status semantics, frozen-input integrity,
human-choice evidence protection, and forecast observation source
attribution. Persistence tests (14) cover deterministic serialization,
content-addressed writes, idempotency, sequence-order preservation, and
frozen input provenance serialization and persistence.

### Final corrections

- Added scenario `decision_at` temporal guard (post-cutoff scenarios rejected).
- Added human-choice `recorded_at` temporal guard (post-cutoff choices rejected).
- Added preserved `actual_choice` consistency check (explicit argument must
  match preserved evidence when it exists).
- Fixed forecast observation `decision_run_id` to attribute human-choice
  projected score to the actual source artefact (baseline, scenario, or
  candidate bundle) rather than always using the baseline run ID.

### Validation

Ruff, strict Pyright, all evaluation tests, persistence tests, and full suite
pass with no regressions.
